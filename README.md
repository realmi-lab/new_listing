# 신규 상장 추적기 (listing-tracker)

업비트·빗썸 원화 마켓에 새로 상장된 코인의 **첫 24시간 거래금액**을 상장(첫 체결) 시각부터
1시간 단위로 쌓아 보여 주는 윈도우 콘솔 프로그램입니다. 실행하면 브라우저에 MarketGo 인덱스2
디자인의 화면이 열립니다. 어두운 화면이 기본이고, 화면 왼쪽 아래 버튼으로 밝은 화면으로 바꿀 수 있습니다.

## 사용법 (윈도우)

1. `listing-tracker.exe`를 실행합니다. 콘솔 창에 진행 상황이 나오고 브라우저가 열립니다
   (기본 주소 `http://127.0.0.1:8770/`).
2. 켜는 순간 최근 7일 안에 처음 거래된 원화 마켓을 찾습니다. 업비트는 요청 한도 때문에 30~40초 걸립니다.
3. 종료하려면 콘솔 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

언제 켜도 최근 7일 안의 상장은 **실제 첫 체결 시각부터** +1시간 … +24시간이 채워집니다.
DB나 별도 서버가 필요 없고, 켤 때마다 거래소 자료로 다시 계산합니다.

### 실행 옵션

| 옵션 | 기본 | 설명 |
| --- | --- | --- |
| `-addr` | `127.0.0.1:8770` | 화면 주소 |
| `-lookback` | `168h` | 켤 때 찾을 상장 기간 (7일) |
| `-watch BTC,ETH` | 없음 | 상장과 관계없이 지금부터 직접 추적할 코인 (시험·확인용) |
| `-upbit-rate 2` | 8 | 업비트 그룹별 초당 요청 상한. 같은 PC(같은 IP)에서 다른 업비트 프로그램을 돌릴 때 낮춥니다 |
| `-no-browser` | 끔 | 켤 때 브라우저를 열지 않음 |
| `-upbit-access-key`, `-upbit-secret-key` | 없음 | 업비트 공지 웹소켓용 API 키 (선택) |

### 업비트 공지 웹소켓 (선택)

업비트 공지 웹소켓은 로그인용(Private) 웹소켓이라 업비트 Open API 키가 필요합니다(별도 권한은 필요 없음).
cmd에서 실행 옵션으로 넣습니다. 설정 파일은 쓰지 않습니다.

```bat
listing-tracker.exe -upbit-access-key 발급받은AccessKey -upbit-secret-key 발급받은SecretKey
```

실행 옵션은 같은 PC의 다른 프로그램이 볼 수 있는 실행 기록에 남을 수 있습니다. 그게 싫으면 환경 변수
`UPBIT_ACCESS_KEY`, `UPBIT_SECRET_KEY`로 넣어도 됩니다(옵션이 있으면 옵션이 우선).

키가 없으면 업비트 웹사이트의 공지 목록을 5초마다 확인합니다. 이 목록은 공식 Open API가 아니어서 바뀔 수 있습니다.
빗썸은 공식 공지 API(`/v1/notices`, IP당 초당 1회)를 3초마다 확인합니다.

## 동작 방식

| 단계 | 자료 | 설명 |
| --- | --- | --- |
| 상장 예고 | 공지 | 업비트(웹소켓 또는 목록)·빗썸(공지 API)의 상장 공지. 공지가 오면 마켓 목록을 바로 다시 확인합니다 |
| 상장 감지 | 마켓 목록 `/v1/market/all` | 5초마다 확인. 처음 받은 목록이 기준이고, 그 뒤 새로 나타난 원화 마켓이 신규 상장입니다 |
| 켤 때 찾기 | 일봉 → 10분봉 → 1분봉 | 첫 일봉이 최근 7일 안이면 신규. 10분봉·1분봉으로 첫 체결 분을 찾습니다. 3일 넘게 쉬었다 다시 거래되면 재상장 |
| 거래금액 | 1분봉 `candle_acc_trade_price` | 끝난 1분은 끝난 뒤 다시 읽어 **확정**, 진행 중인 1분은 1초마다 다시 읽어 **진행 중**으로 표시 |

- **1시간 구간**: 첫 체결 분부터 60분씩입니다. 예: 14:05 첫 체결 → +1시간은 14:05~15:05.
- **같은 코인이 두 거래소에 상장**: 첫 체결이 24시간 안이면 하나로 묶고, 더 이른 첫 체결을 기준으로 합니다.
- **한쪽 거래소만 신규**: 다른 거래소에 이미 있던 마켓도 같은 시간 구간으로 함께 집계해 비중을 보여 줍니다(표의 ★가 신규).
- **빈 구간**: 읽기 실패로 빈 1분은 0으로 채우지 않고 "일부 미확인"으로 표시한 뒤, 다시 읽어 채웁니다.
  거래가 없던 1분은 거래소가 1분봉을 만들지 않으므로 0원입니다.
- **시계**: PC 시계가 틀려도 거래소 응답의 `Date` 헤더로 보정해 1분 경계를 거래소에 맞춥니다.

## 요청 한도

| 거래소 | 공식 한도 (IP 기준) | 이 프로그램의 상한 |
| --- | --- | --- |
| 업비트 | 그룹(market, candle 등)별 초당 10회 | 그룹별 초당 8회, 진행 중 1분 갱신은 초당 4회 안에서 나눔 |
| 빗썸 | 분류별 초당 150회, 공지 초당 1회 | 분류별 초당 50회, 공지 3초마다 |

429·418 응답을 받으면 해당 그룹을 1초부터 최대 1분까지 기다린 뒤 다시 요청합니다.

## 개발

```sh
go test ./...
cd web && npm ci && npm run build
./scripts/build.sh   # dist/listing-tracker.exe (윈도우), dist/listing-tracker (현재 OS)
```

화면만 고칠 때는 프로그램을 `-addr 127.0.0.1:8770`으로 켜고 `cd web && npm run dev`를 쓰면 `/api`가 프로그램으로 연결됩니다.

| 경로 | 역할 |
| --- | --- |
| `cmd/listing-tracker` | 실행 진입점, 콘솔 출력, 브라우저 열기 |
| `internal/registry` | 마켓 목록 감시와 신규 상장 판별 |
| `internal/discovery` | 켤 때 최근 상장 찾기 |
| `internal/candles` | 1분봉·10분봉·일봉 조회와 페이지 넘김 |
| `internal/tracker` | 상장별 1분 확정·진행 중 관리, +1~+24시간 집계, 화면 자료 |
| `internal/notices` | 업비트·빗썸 상장 공지 |
| `internal/restclient` | 거래소별 요청 간격, 429 대기, 거래소 시계 보정 |
| `internal/httpapi` | `/api/snapshot`, `/api/stream`(초당 1회 이벤트), 화면 파일 |
| `web/` | React 화면 (인덱스2 디자인 이식) |

화면 디자인은 MarketGo `frontend/client/src/pages/MarketIndex2.tsx`, `market-index2.css`,
`Index2FilterButton.tsx`에서 가져왔습니다. 이 프로그램은 MarketGo 서버·DB와 연결되지 않습니다.
