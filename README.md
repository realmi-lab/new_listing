# new_listing — 업비트·빗썸 신규 상장 추적기

업비트·빗썸 원화(KRW) 마켓에 새로 상장된 코인의 **상장 후 24시간 거래금액**을, 첫 체결 시각부터
1시간 단위로 보여 주는 윈도우 콘솔 프로그램입니다. 실행하면 이 PC 안에서만 열리는 화면
(`http://127.0.0.1:8770/`)이 브라우저에 뜹니다.

이 문서는 보안 검토용입니다. 프로그램의 기능, 외부 접속, 이 PC에서 하는 일, 실제로 돌아가는 파일과 함수를
모두 적었고, 모든 항목은 이 저장소의 코드와 같습니다.

---

## 1. 보안 요약

- **하는 일**: 거래소의 공개 시세·공지 자료를 **읽기만** 합니다.
- **하지 않는 일**: 로그인, 주문, 출금, 계좌 조회, 개인정보 수집 기능이 없습니다.
- **인증 정보**: API 키·비밀번호·토큰을 받지도, 쓰지도 않습니다.
- **외부 접속**: 아래 네 곳에만 HTTPS GET으로 접속합니다.
  - `api.upbit.com`, `api-manager.upbit.com`
  - `api.bithumb.com`, `feed-api.bithumb.com`
- **외부로 보내는 값**: 마켓 코드(예: `KRW-BTC`), 조회 개수, 조회 기준 시각뿐입니다. 쿠키·식별자·PC 정보는 보내지 않습니다.
- **받는 접속**: `127.0.0.1:8770`(이 PC 안)만 엽니다. 다른 PC에서는 접속할 수 없고, 이를 바꾸는 옵션도 없습니다.
- **파일**: 프로그램이 직접 읽거나 만들거나 쓰는 파일이 없습니다. 설정 파일·DB·로그 파일이 없습니다.
- **권한**: 관리자 권한이 필요 없습니다. 서비스 등록·자동 실행·레지스트리 변경이 없습니다.
- **실행하는 다른 프로그램**: 켤 때 기본 브라우저로 화면 주소를 여는 것 하나뿐입니다(`-no-browser`로 끌 수 있음).
- **업데이트·원격 측정**: 자동 업데이트, 사용 통계 전송이 없습니다.
- **외부 라이브러리**: Go는 표준 라이브러리만 씁니다. 화면은 React와 Pretendard 글꼴을 빌드할 때 실행 파일 안에 넣습니다.
- **종료하면**: 모든 자료가 메모리에만 있으므로 함께 사라집니다.

## 2. 기능

- **신규 상장 감지**
  - 두 거래소의 공식 마켓 목록을 5초마다 확인합니다.
  - 켤 때 처음 받은 목록이 기준이고, 그 뒤 새로 나타난 원화 마켓을 신규 상장으로 봅니다.
  - 빈 응답이나 절반 이하로 줄어든 응답은 거래소 오류로 보고 무시합니다.
- **켤 때 최근 상장 찾기**
  - 원화 마켓마다 일봉을 조회해 첫 거래일이 최근 7일 안이면 신규로 봅니다. 일봉은 이 판단에만 쓰고, 거래금액 계산에는 쓰지 않습니다.
  - 10분봉·1분봉으로 첫 체결 분을 찾습니다.
  - 3일 넘게 거래가 없다가 다시 거래된 마켓은 재상장으로 표시합니다.
- **거래금액 누적**
  - 거래소 공식 1분봉의 거래대금(`candle_acc_trade_price`)을 더합니다.
  - 끝난 1분은 끝난 뒤 다시 읽어 **확정**합니다.
  - 진행 중인 1분은 약 1초마다 다시 읽어 **진행 중**으로 표시합니다.
- **1시간 구간과 24시간 누적**
  - 첫 체결 분부터 60분씩, +1시간부터 +24시간까지 계산합니다.
  - 각 시간 값은 그 60분의 1분봉 거래대금을 더한 값입니다.
  - 24시간 누적은 +1~+24시간 값(시간봉 24개)을 더한 값입니다. 일봉 금액을 쓰지 않습니다.
  - 거래소 공식 60분봉은 정시(14:00~15:00) 기준이라 첫 체결 시각 기준 구간과 맞지 않습니다. 그래서 1분봉으로 구간을 만듭니다.
- **거래소 비교**
  - 같은 코인이 두 거래소에 24시간 안에 상장하면 하나로 묶습니다.
  - 다른 거래소에 이미 있던 코인도 같은 시간 구간으로 계산해 `[신규상장]` / `[기존]`으로 비교합니다.
- **상장 공지**
  - 빗썸 공식 공지 API를 3초마다, 업비트 공지 목록을 5초마다 확인합니다.
  - 상장 공지가 오면 그 거래소의 마켓 목록을 바로 다시 확인합니다.
- **빈 구간 처리**
  - 읽지 못한 1분은 0으로 채우지 않고 "일부 미확인"으로 표시한 뒤, 다시 읽어 채웁니다.
  - 거래가 없던 1분은 거래소가 1분봉을 만들지 않으므로 0원입니다.
- **화면**
  - MarketGo 인덱스2 디자인이고, 다크 모드가 기본입니다.
  - 코인 보기, 시간별 보기(+1~+24), 상장 공지 보기, 선택한 코인의 거래소별 시간표가 있습니다.

## 3. 외부 접속 (데이터 수집)

모든 요청은 HTTPS **GET**이며, 아래 주소 외에는 접속하지 않습니다.

### 마켓 목록 — 신규 상장 감지

- **주소**
  - `https://api.upbit.com/v1/market/all?is_details=true`
  - `https://api.bithumb.com/v1/market/all?isDetails=true`
- **주기**: 5초마다. 상장 공지가 오면 즉시 한 번 더(거래소별 2초에 한 번까지).
- **보내는 값**: 없음.

### 캔들 — 거래금액

- **주소**
  - `https://api.upbit.com/v1/candles/days`, `…/candles/minutes/10`, `…/candles/minutes/1`
  - `https://api.bithumb.com/v1/candles/days`, `…/candles/minutes/10`, `…/candles/minutes/1`
- **주기**
  - 켤 때: 원화 마켓마다 일봉 1번(`count=10`, 첫 거래일 찾기에만 사용), 최근 상장 후보마다 10분봉·1분봉 1번씩.
  - 켜져 있는 동안: 추적 중인 마켓마다 1분봉 약 1초에 1번, 빈 구간은 200개씩, 첫 체결을 기다리는 마켓은 3초에 1번.
- **보내는 값**: `market`(마켓 코드), `count`(개수), `to`(기준 시각).

### 공지 — 상장 예고

- **빗썸**: `https://api.bithumb.com/v1/notices?count=20`
  - 3초마다. 빗썸이 `https://feed-api.bithumb.com/v1/notices?count=20`으로 리다이렉트합니다.
- **업비트**: `https://api-manager.upbit.com/api/v1/announcements?os=web&page=1&per_page=20&category=trade`
  - 5초마다. 공식 Open API가 아닌, 업비트 웹사이트가 쓰는 공지 목록 주소입니다.

### 모든 요청에 공통

- **헤더**: `Accept: application/json`, `User-Agent: listing-tracker/1`만 보냅니다. 쿠키를 저장하거나 보내지 않습니다.
- **리다이렉트**: 최대 3번까지, `upbit.com`·`bithumb.com` 도메인의 https 주소로만 따라갑니다.
- **응답 처리**: 8MB까지만 읽습니다. JSON 형식이 아니거나 값이 음수면 버립니다.
- **시간 제한**: 요청마다 5~8초, 여러 페이지를 읽는 작업은 60초입니다.
- **PC 시계 보정**: 거래소 응답의 `Date` 헤더로 PC 시계를 보정해, 1분 경계를 거래소 시각에 맞춥니다.

### 요청 한도

| 거래소 | 공식 한도 (IP 기준) | 이 프로그램 |
| --- | --- | --- |
| 업비트 | 그룹별 초당 10회 | 그룹별 초당 8회 |
| 빗썸 | 분류별 초당 150회 | 분류별 초당 50회 |
| 빗썸 공지 | 초당 1회 | 1.1초에 1회 |

- **진행 중 1분 갱신**: 업비트는 전체 초당 4회, 빗썸은 초당 10회 안에서 나눕니다.
- **업비트 공지 목록**: 3초에 1회 이하로 요청합니다.
- **429·418 응답**: 거래소가 429(요청 초과)나 418(일시 차단)을 보내면 그 그룹을 1초부터 최대 60초까지 기다립니다. 418이면 바로 60초를 기다립니다.
- **남은 횟수 헤더**: 업비트 `Remaining-Req`의 초당 남은 횟수가 1 이하이면 다음 초까지 기다립니다.
- **같은 PC의 다른 업비트 프로그램**: 업비트 한도는 IP별이라 나눠 씁니다. `-upbit-rate`로 상한을 낮출 수 있습니다.

## 4. 이 PC에서 하는 일

- **여는 포트**: `127.0.0.1:8770` 하나.
  - 주소는 항상 `127.0.0.1`(이 PC 안)로 고정입니다.
  - 다른 프로그램과 겹칠 때만 `-port`로 번호를 바꿀 수 있습니다.
- **화면 주소의 기능**: 읽기만 있고, 쓰기·변경 요청은 없습니다.
  - `GET /api/snapshot`: 화면 자료(JSON)
  - `GET /api/stream`: 1초마다 자료를 보내는 이벤트 스트림(동시 64개까지)
  - `GET /`: 화면 파일
  - GET이 아닌 요청은 405로 거부합니다.
- **화면 주소 보호**
  - `Host`가 `127.0.0.1`·`localhost`·`[::1]`(같은 포트)가 아니면 403으로 거부합니다. 다른 웹사이트가 DNS 리바인딩으로 읽는 것을 막습니다.
  - 응답 헤더 `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, 자료 응답은 `Cache-Control: no-store`.
- **파일**: 프로그램이 직접 읽거나 쓰는 파일이 없습니다. 화면 파일은 실행 파일 안에 들어 있고, 바깥 파일을 읽는 옵션이 없습니다.
- **브라우저 저장**: 화면 밝기 선택 하나만 `localStorage`의 `listing-tracker-theme`에 저장합니다.
- **화면이 접속하는 곳**
  - 같은 주소의 `/api/stream`, `/api/snapshot`뿐입니다. 글꼴·스크립트를 외부(CDN)에서 받지 않습니다.
  - 공지 제목을 누르면 거래소 공지 페이지가 새 탭으로 열립니다(`rel="noreferrer noopener"`).
- **실행하는 프로그램**: 켤 때 화면 주소를 기본 브라우저로 엽니다. `-no-browser`로 끌 수 있습니다.
  - 윈도우: `rundll32 url.dll,FileProtocolHandler http://127.0.0.1:8770/`
  - macOS: `open`, 리눅스: `xdg-open`
- **윈도우 API**: `kernel32.dll`의 `SetConsoleOutputCP(65001)`, `SetConsoleCP(65001)`. 콘솔의 한글이 깨지지 않게 UTF-8로 바꾸는 것뿐입니다.
- **콘솔 출력**: 진행 상황(상장 감지, 최근 상장, 오류)을 콘솔 창에만 출력합니다.

## 5. 실제로 돌아가는 내용

### 켤 때 순서

1. `main.go` `main()`: 윈도우면 콘솔을 UTF-8로 바꿉니다(`console_windows.go` `useUTF8Console()`).
2. `main.go` `run()`: 실행 옵션을 읽고 부품을 만듭니다.
   - 외부 요청 출입구 `restclient.New()`
   - 캔들 조회 `candles.NewClient()`
   - 추적 저장소(메모리) `tracker.New()`
   - 마켓 목록 감시 `registry.New()`
   - 최근 상장 찾기 `discovery.New()`
   - 공지 감시 `notices.NewWatcher()`
3. `127.0.0.1:8770`을 열고, `httpapi` `LoopbackOnly()`로 `Host` 확인을 켭니다.
4. 콘솔에 시작 요약을 출력합니다(`console.go` `banner()`).
5. 아래 작업들을 동시에 시작합니다.
6. 기본 브라우저로 화면 주소를 엽니다(`main.go` `openBrowser()`, `-no-browser`면 생략).
7. Ctrl+C(종료 신호)를 받으면 화면 서버를 닫고 모든 작업을 멈춘 뒤 끝냅니다.

### 켜져 있는 동안 돌아가는 작업

| 작업 | 주기 |
| --- | --- |
| 마켓 목록 감시 (거래소별) | 5초 |
| 최근 상장 찾기 (거래소별) | 켤 때 한 번 |
| 1분봉 수집 (거래소별) | 추적 중인 마켓당 약 1초 |
| 공지 감시 (거래소별) | 빗썸 3초, 업비트 5초 |
| 상태 정리 | 1초 |
| 화면 서버 | 요청이 올 때 |

#### 마켓 목록 감시

- **담당**: `registry.go` `Run()` → `PollOnce()` → `Diff()`
- **하는 일**: 마켓 목록을 받아 이전 목록과 비교합니다. 새 원화 마켓이면 `tracker.AddListing()`에 넘깁니다.

#### 최근 상장 찾기

- **담당**: `main.go` `scan()` → `discovery.go` `Scan()` → `check()`
- **하는 일**: 첫 마켓 목록을 받은 뒤 원화 마켓마다 일봉을 봅니다. 최근 7일 안에 처음 거래된 마켓의 첫 체결 분을 찾아 `tracker.AddListing()`에 넘깁니다.

#### 1분봉 수집

- **담당**: `fetch.go` `RunFetcher()` → `nextJob()` → `planLocked()` → `execute()` → `apply()`
- **하는 일**: 마켓마다 필요한 일을 하나 고릅니다.
  - 첫 체결 찾기
  - 빈 구간 채우기(`candles.go` `MinuteRange()`)
  - 최신 몇 분 다시 읽기(`candles.go` `Minutes()`)
- 끝난 1분은 확정하고, 진행 중인 1분은 갱신합니다.

#### 공지 감시

- **담당**: `watcher.go` `Run()` → `poll()` → `notices.go` `ParseBithumb()` · `ParseUpbitList()` → `Classify()`
- **하는 일**: 공지 목록에서 상장 공지를 골라 `tracker.AddNotice()`에 넣습니다. 새 상장 공지면 그 거래소의 마켓 목록을 바로 다시 확인합니다.

#### 상태 정리

- **담당**: `tracker.go` `Maintain()`
- **하는 일**: 7일이 지난 추적을 지우고, 같은 코인을 가진 다른 거래소 마켓을 붙이고, `-watch` 코인을 시작합니다.

#### 화면 서버

- **담당**: `server.go` `Handler()` → `snapshot.go` `Snapshot()`
- **하는 일**: 메모리의 자료로 +1~+24시간, 누적, 최근 60분, 비중을 계산해 JSON으로 보냅니다. `/api/stream`은 1초마다 보냅니다.

모든 외부 요청은 `restclient.go` `Get()` 하나를 거칩니다. 요청 간격, 429·418 대기, 응답 8MB 제한, 리다이렉트 제한이 여기서 적용됩니다.

### 자료 흐름

```text
업비트·빗썸 마켓 목록   ──▶ registry  (신규 상장 판별) ──┐
켤 때 일봉·10분봉·1분봉 ──▶ discovery (최근 7일 상장)  ──┤
업비트·빗썸 공지 목록   ──▶ notices   (상장 공지 판별) ──┼──▶ tracker (메모리) ──▶ snapshot ──▶ 화면 (127.0.0.1:8770)
추적 중 마켓 1분봉      ──▶ fetch     (확정·진행 중)   ──┘

외부 요청은 모두 restclient.Get() → 업비트·빗썸 HTTPS GET
```

## 6. Go 파일별 기능

실행 파일에 들어가는 Go 파일입니다. 모두 표준 라이브러리만 사용합니다.

### `cmd/listing-tracker/` — 실행 진입점

#### `main.go`
- 프로그램 시작과 종료, 부품 연결.
- `run()`: 옵션을 읽고 부품을 만들어 모든 작업을 시작합니다.
- `scan()`: 첫 마켓 목록을 받은 뒤 최근 상장 찾기를 시작합니다.
- `openBrowser()`: 화면 주소를 기본 브라우저로 엽니다.

#### `console.go`
- 콘솔 출력.
- `banner()`: 시작 요약을 출력합니다.
- `line()`: `시각  거래소  내용` 한 줄을 출력합니다.
- `usage()`: `-h` 한글 안내를 출력합니다.
- `consoleHandler`: 경고·오류를 `시각  경고  내용` 형식으로 출력합니다.

#### `console_windows.go`
- 윈도우 전용.
- `useUTF8Console()`: `kernel32.dll`의 `SetConsoleOutputCP`·`SetConsoleCP`(65001)로 콘솔을 UTF-8로 바꿉니다.

#### `console_other.go`
- 윈도우가 아닌 OS용 빈 함수입니다.

### `internal/` — 기능 부품

#### `market/market.go`
- 거래소·마켓 정의와 마켓 목록 주소.
- `ParseMarketList()`: 마켓 목록 응답에서 원화 마켓만 꺼냅니다. JSON 배열이 아니면 거부합니다.

#### `registry/registry.go`
- 신규 상장 감지. 아무것도 저장하지 않습니다.
- `Run()`·`PollOnce()`: 거래소별로 5초마다 마켓 목록을 받습니다.
- `Diff()`: 새 목록과 아는 목록을 비교합니다.
  - 첫 목록은 기준입니다.
  - 새로 나타난 원화 마켓은 신규, 빠졌다가 다시 나타난 마켓은 재상장입니다.
  - 3번 연속 빠져야 목록에서 지웁니다.
  - 빈 응답이나 절반 이하로 줄어든 응답은 거부합니다.
- `ActiveMarketsForBase()`: 같은 코인을 가진 거래소를 알려 줍니다.

#### `discovery/discovery.go`
- 켤 때 최근 상장 찾기.
- `Scan()`: 원화 마켓마다 `check()`를 부릅니다.
- `check()`: 일봉 → 10분봉 → 1분봉 순서로 첫 체결 분을 찾습니다. 여기서 쓰는 일봉·10분봉은 시각 찾기용이고, 금액에는 쓰지 않습니다.
- `firstDayInWindow()`: 첫 거래일(또는 3일 넘게 쉬고 다시 거래된 날)이 최근 7일 안인지 판단합니다.
- `Progress()`: 진행률을 화면에 줍니다.

#### `candles/candles.go`
- 캔들 조회.
- `Minutes()`·`Days()`: 1분봉·10분봉·일봉을 요청합니다.
- `Parse()`: 응답을 읽습니다. 음수나 잘못된 형식은 거부합니다.
- `MinuteRange()`: 원하는 구간의 1분봉을 200개씩 거꾸로 넘겨 가며 모읍니다.
- `formatTo()`: 거래소마다 다른 기준 시각 형식을 만듭니다(업비트 UTC, 빗썸 한국시각).

#### `tracker/tracker.go`
- 추적 대상 관리(메모리).
- `AddListing()`: 상장을 받아 코인별 추적을 만들거나, 24시간 안의 같은 코인과 묶습니다. 기준 시각은 신규 마켓 중 가장 이른 첫 체결입니다.
- `Maintain()`: 1초마다 7일 지난 추적을 지우고, 같은 코인을 가진 다른 거래소 마켓을 붙입니다.
- `AddManual()`: `-watch`로 지정한 코인을 받습니다.
- `AddNotice()`: 공지를 받습니다.

#### `tracker/fetch.go`
- 1분봉 수집 순서.
- `RunFetcher()`: 거래소마다 하나씩 돌며 작업을 처리합니다.
- `nextJob()`: 가장 오래 기다린 마켓을 고릅니다.
- `planLocked()`: 그 마켓에 필요한 일을 정합니다(첫 체결 찾기, 빈 구간 채우기, 최신 몇 분 다시 읽기).
- `apply()`: 결과를 넣습니다. 실패하면 2초부터 최대 60초까지 기다린 뒤 다시 합니다.
- `addFinal()`: 끝난 1분을 확정 구간에 넣습니다. 확정 구간은 항상 끊김 없이 이어져 있습니다.

#### `tracker/snapshot.go`
- 화면 자료 계산. 비중은 여기서 계산하고, 화면은 받은 값을 그대로 보여 줍니다.
- `Snapshot()`: 코인별 +1~+24시간, 누적, 최근 60분, 거래소별 비중, 공지 연결을 만듭니다. 시간 값은 1분봉 60개의 합이고, 누적은 시간 값의 합입니다.
- `minute()`: 1분을 확정·진행 중·미확인으로 구분합니다.
- `span()`·`combine()`: 구간 합계와 상태(확정, 진행 중, 확정 중, 일부 미확인, 대기, 미상장)를 정합니다.

#### `notices/notices.go`
- 공지 해석.
- `ParseBithumb()`·`ParseUpbitList()`: 공지 목록을 읽습니다.
- `Classify()`: 제목으로 상장 공지를 판별합니다.
  - 상장 공지로 보는 말: "신규 거래지원", "디지털 자산 추가", "마켓 추가" 등
  - 빼는 말: "종료", "유의", "이벤트", "에어드랍" 등
  - 괄호 안의 코인 기호와 원화 마켓 여부를 꺼냅니다.

#### `notices/watcher.go`
- 공지 감시.
- `Run()`: 빗썸 공지를 3초마다, 업비트 공지 목록을 5초마다 읽습니다.
- `Statuses()`: 마지막 성공·오류를 화면에 줍니다.

#### `restclient/client.go`
- 모든 외부 요청의 출입구.
- `Get()`: 거래소·그룹별 간격을 지키며 GET을 보내고, 응답을 8MB까지 읽습니다. 429·418이면 기다리고, 업비트 `Remaining-Req`를 따릅니다.
- `NewHTTPClient()`: 리다이렉트를 거래소 도메인의 https로만 허용합니다.
- `Now()`: `Date` 헤더로 보정한 시각입니다.
- `SetUpbitRate()`: `-upbit-rate` 옵션을 적용합니다.

#### `httpapi/server.go`
- 이 PC 안의 화면 서버.
- `Handler()`: `/api/snapshot`, `/api/stream`, 화면 파일을 GET으로만 제공합니다.
- `LoopbackOnly()`·`checkHost()`: 이 PC 이름이 아닌 `Host`를 거부합니다.
- `stream()`: 동시 64개까지 1초마다 자료를 보냅니다.
- 자료는 0.5초 동안 재사용해, 보는 사람이 많아도 계산이 늘지 않습니다.

#### `webui/webui.go`
- 빌드한 화면 파일을 실행 파일 안에 넣습니다(`go:embed`).

## 9. 빌드와 검증

- **필요한 것**: Go 1.26 이상, Node.js와 npm.
- **이 저장소 결과물의 빌드 환경**: Go 1.27.0, Node 26.8.1.

```sh
VERSION=1.0.0 ./scripts/build.sh
```

`scripts/build.sh`가 하는 일:

1. `web/`에서 `npm ci`(잠금 파일 그대로 설치)와 `npm run build`(타입 검사와 화면 묶기)
2. 묶은 화면을 `internal/webui/dist/`로 복사
3. `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=$VERSION"`
   → `dist/listing-tracker.exe`, 같은 방식으로 현재 OS용 `dist/listing-tracker`

같은 커밋을 같은 Go·Node 버전과 같은 `VERSION`으로 두 번 빌드하면 같은 SHA-256이 나오는 것을 확인했습니다.
검토한 원본과 배포 파일이 같은지 이렇게 확인할 수 있습니다.

```sh
VERSION=1.0.0 ./scripts/build.sh && shasum -a 256 dist/listing-tracker.exe
```

`dist/`(실행 파일)와 화면 빌드 결과는 저장소에 올리지 않습니다.

## 10. 사용법

`listing-tracker.exe`를 실행하면 콘솔 창에 진행 상황이 나오고 브라우저가 열립니다.
끌 때는 창을 닫거나 `Ctrl+C`를 누릅니다.

| 옵션 | 기본 | 설명 |
| --- | --- | --- |
| `-watch BTC,ETH` | 없음 | 지금부터 직접 추적할 코인 |
| `-no-browser` | 끔 | 브라우저를 열지 않음 |
| `-port` | `8770` | 화면 포트 (주소는 항상 127.0.0.1) |
| `-lookback` | `168h` | 켤 때 찾을 상장 기간 (7일) |
| `-registry-interval` | `5s` | 마켓 목록 확인 간격 |
| `-upbit-rate` | `8` | 업비트 그룹별 초당 요청 상한 |
| `-verbose` | 끔 | 자세한 기록 출력 |

다른 PC에서 접속하게 하는 옵션은 없습니다. 화면은 이 PC의 브라우저에서만 열립니다.

## 11. 알려진 제한

- 업비트 공지 목록 주소(`api-manager.upbit.com`)는 공식 Open API가 아니어서 바뀌거나 막힐 수 있습니다. 막혀도 상장 감지는 마켓 목록으로 계속됩니다.
- 켤 때 찾기는 최근 7일만 봅니다. 그보다 오래된 상장은 `-watch`로 직접 추가해야 하고, 이때는 켠 시각부터 셉니다.
- 거래소가 1분봉을 늦게 고치면, 이미 확정한 1분에는 반영되지 않습니다.
- 서명되지 않은 실행 파일이라 윈도우가 처음 실행할 때 경고를 띄울 수 있습니다.
